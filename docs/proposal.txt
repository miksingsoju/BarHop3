2. Description of the App
BarHop is a web service that helps the Ateneo community, especially students heading out after exams, org events, or Friday classes, find out which bars around Katipunan, Maginhawa, Poblacion, and BGC are lively right now and reserve a table ahead of time. Today this is mostly guesswork based on group chats and word of mouth.
Bar Hoppers who are at a bar can give it a timed like. Each like counts toward the bar's activity for 90 minutes and then expires. From the number of active likes, BarHop gives each bar a status: QUIET (0–4), MODERATE (5–14), LIVELY (15–29), or PACKED (30+). A scheduled job removes expired likes every minute so the statuses stay current. Hoppers can also leave 0–5 star reviews, which stay on the bar's page and update its average rating, and they can reserve a table for a date, time window, and party size. BarHop will not book the same table twice for overlapping times.
Bar Owners have separate accounts. They list their bars (only bars inside Metro Manila are accepted), register bookable tables, post events, and confirm reservations or mark them as no-shows. Through Twilio (called with Retrofit), BarHop texts the hopper when a booking is placed, confirmed, or cancelled, texts the owner when a new booking arrives, and sends the hopper a reminder about two hours before the reservation.
This project builds on our earlier BarHop SRS and SDD. The backend is now a Spring Boot service (Jersey, Spring Data JPA, Javax Validation, Retrofit, Scheduling) instead of Django, and the user interface will be built in Next.js instead of Django templates.

3. Controller Operations
GET is used for retrieval and POST for all submits. Request and response bodies are JSON. Every error is returned in this format (validation errors also include an errors array listing each invalid field):
{
  "status": 404,
  "error": "Not Found",
  "message": "Bar with id 99 does not exist.",
  "timestamp": "2026-11-20T21:05:12"
}

4. Components
Each component is a Spring @Component (business methods are @Transactional). Controllers get them through @Autowired. For each important method, the steps below are what the method does, in order.
4.1 HopperComponent
Handles Bar Hopper accounts: registration, login, profile updates, and deletion. It makes sure one email cannot be both a hopper and an owner (SRS 2.5).
registerHopper(HopperRequest req)
	•	Normalize the email (trim, lowercase).
	•	If hopperRepository.existsByEmailIgnoreCase(email) or ownerRepository.existsByEmailIgnoreCase(email) → throw 409 Conflict.
	•	Hash the password with BCrypt.
	•	Build a Hopper entity, set createdAt = now(), and save it.
	•	Return a HopperResponse DTO without the password.
login(LoginRequest req)
	•	Look up hopperRepository.findByEmailIgnoreCase(email); if not found → 401.
	•	Compare the password with the stored BCrypt hash; if it does not match → 401.
	•	Return a HopperResponse.
getAllHoppers() / getHopper(Long id)
	•	Call findAll() or findById(id) (throw 404 if empty).
	•	Map the entities to response DTOs.
updateHopper(Long id, HopperUpdateRequest req)
	•	Load the hopper or throw 404.
	•	Copy over the non-null fields (first name, last name, phone number).
	•	Save and return the DTO.
deleteHopper(Long id)
	•	Load the hopper or throw 404.
	•	Find upcoming PENDING/CONFIRMED reservations with reservationRepository.findByHopperIdAndStatusIn(...) and call ReservationComponent.cancelBySystem(...) on each (this notifies the owner).
	•	Delete the hopper's likes (timedLikeRepository.deleteByHopperId) and reviews. Recalculate the average rating of every bar the hopper reviewed.
	•	Delete the hopper and return a summary message.
4.2 OwnerComponent
Handles Bar Owner accounts. Its methods mirror HopperComponent.
registerOwner(OwnerRequest req)
	•	Normalize the email; throw 409 if a hopper or owner already uses it.
	•	Hash the password, build the Owner, set createdAt, and save.
	•	Return an OwnerResponse with barCount = 0.
login(LoginRequest req)
	•	ownerRepository.findByEmailIgnoreCase(email) → 401 if not found.
	•	Check the BCrypt hash → 401 if it does not match.
	•	Return an OwnerResponse with barCount = barRepository.countByOwnerId(id).
getAllOwners() / getOwner(Long id) / updateOwner(...)
	•	Load the owner(s), or throw 404.
	•	For updates, copy the non-null fields and save.
	•	Map to DTOs, filling in barCount.
deleteOwner(Long id)
	•	Load the owner or throw 404.
	•	If barRepository.countByOwnerId(id) > 0 → throw 409.
	•	Delete the owner and return a message.
4.3 BarComponent
Handles bar listings: search, details, and owner-only create/update/delete. It enforces the Metro Manila rule and keeps each bar's average rating up to date.
searchBars(String city, String search, String status, String sort)
	•	Check that status is an ActivityStatus value and sort is likes or rating; otherwise throw 400.
	•	Choose a repository query: findByNameContainingIgnoreCase when search is given, findByCityIgnoreCase when city is given, findByActivityStatus when status is given, otherwise findAllByOrderByActiveLikeCountDesc().
	•	Apply any remaining filters in memory.
	•	Sort by activeLikeCount (default) or averageRating, highest first.
	•	Map to BarSummary DTOs (an empty list is a valid result).
getBar(Long id)
	•	barRepository.findById(id) or throw 404.
	•	Map to BarDetail, including the owner's name and the review count.
createBar(BarRequest req)
	•	Load the owner by req.ownerId or throw 404.
	•	Check that req.city is in the METRO_MANILA_CITIES set (the 17 LGUs); otherwise throw 400.
	•	Build the Bar with averageRating = 0, activeLikeCount = 0, activityStatus = QUIET, and createdAt = now().
	•	Save and return a BarDetail.
updateBar(Long id, BarRequest req)
	•	Load the bar or throw 404.
	•	If bar.owner.id != req.ownerId → throw 403.
	•	Check the Metro Manila city again, copy the fields, and save.
deleteBar(Long id, Long ownerId)
	•	Load the bar, check ownership (403).
	•	Cancel upcoming reservations through ReservationComponent.cancelBySystem(...), which texts each hopper.
	•	Delete the bar. Tables, events, likes, and reviews are removed through CascadeType.REMOVE.
	•	Return the number of reservations that were cancelled.
recalculateRating(Long barId)
	•	Call reviewRepository.averageRatingForBar(barId) (null → 0.0).
	•	Round to one decimal place, store it in bar.averageRating, and save. ReviewComponent calls this.
4.4 TableComponent
Handles each bar's bookable tables and works out which ones are free for a time slot.
getTablesForBar(Long barId)
	•	Check that the bar exists (404).
	•	Return barTableRepository.findByBarIdOrderByLabelAsc(barId) as DTOs.
getAvailableTables(Long barId, LocalDate date, LocalTime start, LocalTime end, int guests)
	•	Check that the bar exists (404), the date is not in the past, end is after start (an overnight slot is allowed when the bar closes after midnight), and the slot falls within operating hours. Otherwise throw 400.
	•	Get candidate tables with barTableRepository.findByBarIdAndActiveTrueAndCapacityGreaterThanEqual(barId, guests).
	•	For each candidate, drop it if reservationRepository.existsByTableIdAndReservationDateAndStartTimeLessThanAndEndTimeGreaterThanAndStatusIn(tableId, date, end, start, [PENDING, CONFIRMED]) is true.
	•	Return the remaining tables, smallest capacity first.
createTable / updateTable(...)
	•	Load the bar or table (404) and check that the caller owns the bar (403).
	•	When creating, throw 409 if existsByBarIdAndLabelIgnoreCase is true.
	•	Save and return the DTO.
deleteTable(Long id, Long ownerId)
	•	Load the table and check ownership.
	•	If reservationRepository.countByTableIdAndReservationDateGreaterThanEqualAndStatusIn(id, today, [PENDING, CONFIRMED]) > 0 → throw 409.
	•	Delete the table.
4.5 EventComponent
Handles event schedules for bars.
getEvents(Long barId, boolean upcomingOnly)
	•	If barId is given, check that the bar exists (404).
	•	Use findByBarIdAndStartDateTimeAfterOrderByStartDateTimeAsc, findByBarIdOrderByStartDateTimeAsc, or findByStartDateTimeAfterOrderByStartDateTimeAsc, depending on the parameters.
	•	Map to DTOs.
createEvent(EventRequest req)
	•	Load the bar (404) and check ownership (403).
	•	Check that endDateTime is after startDateTime (400).
	•	Save and return the DTO.
deleteEvent(Long id, Long ownerId)
	•	Load the event (404) and check ownership (403), then delete.
4.6 ReservationComponent
Handles table bookings from start to finish. It enforces capacity, operating hours, and no double booking, and triggers the SMS notifications.
createReservation(ReservationRequest req)
	•	Load the hopper and the table (404 for either). Get the bar from the table.
	•	If agreedToPolicy is not true → 400. If guestCount > table.capacity → 400.
	•	Call TableComponent.validateSlot(bar, date, start, end) to check the date, time order, and operating hours (400).
	•	Check for overlaps with existsByTableIdAndReservationDateAndStartTimeLessThanAndEndTimeGreaterThanAndStatusIn(...); if any → 409.
	•	Save a Reservation with status = PENDING, reminderSent = false, and createdAt = now().
	•	Call NotificationComponent.reservationPlaced(reservation), which texts the hopper and the owner (failures are logged only).
	•	Return the DTO.
updateStatus(Long id, StatusUpdateRequest req)
	•	Load the reservation (404) and check that req.ownerId owns its bar (403).
	•	Check the change is allowed: PENDING → CONFIRMED/CANCELLED; CONFIRMED → NO_SHOW/COMPLETED/CANCELLED. Anything else → 409.
	•	Save the change. If the new status is CONFIRMED, call NotificationComponent.reservationConfirmed(...); if CANCELLED, call reservationCancelledByBar(...).
cancelReservation(Long id, Long hopperId)
	•	Load the reservation (404) and check the hopper owns it (403).
	•	If the status is COMPLETED, NO_SHOW, or CANCELLED → 409.
	•	Set the status to CANCELLED, save, and call NotificationComponent.reservationCancelledByHopper(...).
getReservations(Long hopperId, Long barId, LocalDate date)
	•	If neither id is given → 400.
	•	For a hopper: findByHopperIdOrderByReservationDateDescStartTimeDesc. For a bar: findByTableBarIdAndReservationDateOrderByStartTimeAsc when date is given, otherwise findByTableBarIdAndReservationDateGreaterThanEqualOrderByReservationDateAsc(today).
	•	Map to DTOs.
deleteReservation(Long id, Long ownerId)
	•	Load the reservation and check the owner (404/403).
	•	Throw 409 unless the status is CANCELLED, COMPLETED, or NO_SHOW.
	•	Delete it.
sendUpcomingReminders()  (called by the scheduler)
	•	Compute now and now + 2h (Asia/Manila).
	•	Get findByStatusAndReminderSentFalseAndReservationDate(CONFIRMED, today) (also tomorrow's early-morning slots when the window crosses midnight).
	•	For each booking whose start time falls in the window, call NotificationComponent.reservationReminder(...) and set reminderSent = true.
	•	Save them all.
closeOutPastReservations()  (called by the scheduler)
	•	Get findByReservationDateBeforeAndStatusIn(today, [PENDING, CONFIRMED]).
	•	Set CONFIRMED → COMPLETED and PENDING (never confirmed) → CANCELLED.
	•	Save them all and log the counts.
4.7 ReviewComponent
Handles reviews and ratings that do not expire (SRS 4.3), and keeps each bar's average rating correct.
createReview(ReviewRequest req)
	•	Load the hopper and bar (404).
	•	If reviewRepository.existsByHopperIdAndBarId(...) → 409.
	•	Save the review with createdAt = updatedAt = now().
	•	Call BarComponent.recalculateRating(barId) and return the DTO.
updateReview(Long id, ReviewRequest req)
	•	Load the review (404) and check the author (403).
	•	Update the rating, comment, and visit date, set updatedAt, and save.
	•	Recalculate the bar's rating.
deleteReview(Long id, Long hopperId)
	•	Load the review and check the author.
	•	Delete it, recalculate the bar's rating, and return the new average.
getReviews(Long barId, Long hopperId)
	•	Throw 400 if neither id is given; throw 404 if the given parent does not exist.
	•	findByBarIdOrderByCreatedAtDesc or findByHopperIdOrderByCreatedAtDesc → DTOs.
4.8 LikeComponent
Handles timed likes and works out each bar's live activity status (SRS 4.1 and 4.2).
likeBar(LikeRequest req)
	•	Load the hopper and bar (404).
	•	If timedLikeRepository.existsByHopperIdAndBarIdAndExpiresAtAfter(hopperId, barId, now) → 409, giving the existing expiry time.
	•	Save a TimedLike with likedAt = now and expiresAt = now + 90 min.
	•	Call refreshBarActivity(bar) and return the like with the bar's new count and status.
removeLike(Long id, Long hopperId)
	•	Load the like (404, also when it has already expired) and check the hopper (403).
	•	Delete it and call refreshBarActivity(bar).
getActiveLikes(Long barId, Long hopperId) / getActivity(Long barId)
	•	Check the parameters (400) and that the bar or hopper exists (404).
	•	Use findByBarIdAndExpiresAtAfter(barId, now) or findByHopperIdAndExpiresAtAfter(hopperId, now); for activity, countByBarIdAndExpiresAtAfter(barId, now).
	•	Return the DTOs.
refreshBarActivity(Bar bar)
	•	count = timedLikeRepository.countByBarIdAndExpiresAtAfter(bar.id, now).
	•	status = count ≥ 30 ? PACKED : count ≥ 15 ? LIVELY : count ≥ 5 ? MODERATE : QUIET.
	•	Save bar.activeLikeCount and bar.activityStatus.
expireLikes()  (called by the scheduler)
	•	expired = timedLikeRepository.findByExpiresAtBefore(now).
	•	Collect the set of affected bar ids, then call deleteAllInBatch(expired).
	•	Call refreshBarActivity for each affected bar, and return the number of likes removed for logging.
4.9 NotificationComponent (Twilio through Retrofit)
Builds SMS messages and sends them through the Twilio Messaging API. It uses a Retrofit interface TwilioApi (@FormUrlEncoded @POST("2010-04-01/Accounts/{accountSid}/Messages.json") with @Field("To"), @Field("From"), @Field("Body")). A RetrofitConfig @Configuration creates it with base URL https://api.twilio.com/, a Jackson converter, and an OkHttp interceptor that adds HTTP Basic auth from twilio.account-sid and twilio.auth-token in application.properties.
sendSms(String to, String body)
	•	Skip the send and log it if twilio.enabled=false (local or offline demos).
	•	Call twilioApi.sendMessage(accountSid, to, fromNumber, body).execute().
	•	If the response is successful, log the returned message sid; otherwise log the Twilio error code. Never throw to the caller.
reservationPlaced / reservationConfirmed / reservationCancelledByHopper / reservationCancelledByBar / reservationReminder(Reservation r)
	•	Write the message text, e.g. "BarHop: Your table VIP Booth 1 at The Kati Taproom on Dec 11, 21:00–23:00 for 6 is PENDING. Ref #7."
	•	Choose the recipients (the hopper's contactNumber, the owner's phoneNumber, or both).
	•	Call sendSms for each recipient.
4.10 ScheduledTasks

5. Entities and Repositories
5.1 Entities
BarHop has eight JPA entities, based on the data dictionary in the original SDD. All ids are Long and generated with @GeneratedValue(strategy = IDENTITY). Each entity is listed with what it represents, why it needs its own table, and its fields with validation rules.
5.1.1 Hopper
A Bar Hopper, meaning a student or customer who browses, likes, reviews, and reserves. Hoppers own likes, reviews, and reservations, and their phone number is where SMS messages go.
